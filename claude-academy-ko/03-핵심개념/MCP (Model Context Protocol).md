# MCP (Model Context Protocol)
> [!tip] 한 문장
> AI와 외부 시스템을 잇는 **USB-C 규격**. 도구마다 따로 붙이던 연결을 하나의 표준으로 바꾼다.

---

## 해결하는 문제
AI 앱 M개 × 데이터 소스 N개 = M×N개의 개별 연동.
MCP는 이걸 **M+N**으로 줄인다. 서버를 한 번 만들면 MCP를 지원하는 모든 클라이언트가 쓴다.

---

## 구조
```
  호스트(Claude Desktop / Claude Code)
        └─ 클라이언트 ──(MCP)── 서버 ── 실제 시스템(DB, API, 파일)
```

## 서버가 제공하는 3가지
| 원시 요소 | 무엇인가 | 누가 주도하나 |
|---|---|---|
| **Tools** | 모델이 호출하는 함수 (예: `예약조회`) | 모델 |
| **Resources** | 읽을 수 있는 데이터 (파일, 레코드) | 애플리케이션 |
| **Prompts** | 미리 만든 프롬프트 템플릿 | 사용자 |

---

## 언제 MCP를 쓰나
- Claude가 **살아 있는 데이터**를 봐야 할 때 (DB, 예약 현황, 캘린더)
- Claude가 **외부에 행동**해야 할 때 (레코드 생성, 메시지 발송)
- 그 연결을 **여러 곳에서 재사용**하고 싶을 때

> [!note] Skills와의 구분
> - **Skills** = 절차 지식(how). 파일 몇 개면 끝.
> - **MCP** = 시스템 연결(access). 서버를 띄워야 함.
> 반복 절차만 필요하면 Skills가 훨씬 싸다.

---

## 보안 경계 (중요)
MCP 서버는 실제 시스템 접근 권한을 갖는다.
- 읽기/쓰기 권한을 **최소로** 설계
- 민감 테이블(환자 식별정보)은 서버 레벨에서 차단
- 서버가 돌려주는 데이터는 **외부 입력**으로 취급 — 지시문처럼 따르지 않게
