# 권한 모델과 안전장치
> [!tip] 한 문장
> Claude Code에게 얼마나 자유를 줄지는 **되돌릴 수 있느냐**로 정한다.

---

## 위험도 3단계
| 등급 | 작업 | 태도 |
|---|---|---|
| 🟢 되돌릴 수 있음 | 파일 읽기, 검색, 테스트 실행 | 자유롭게 허용 |
| 🟡 되돌리기 번거로움 | 파일 수정, 커밋 | 브랜치·커밋으로 보호 |
| 🔴 되돌릴 수 없음 | 배포, DB 마이그레이션, 삭제, 외부 발송 | **매번 직접 확인** |

---

## 실전 안전장치
1. **작업 전 브랜치를 판다.** 최악의 경우 브랜치를 버리면 끝.
2. **커밋을 자주.** 되돌릴 지점을 촘촘히 만든다.
3. **프로덕션 DB 자격증명은 세션에 두지 않는다.**
4. **Plan 모드로 먼저 계획을 본다.** 긴 작업일수록.
5. **테스트가 곧 안전벨트.** 테스트가 있으면 자율성을 더 줘도 된다.

> [!danger] 개원가 특칙
> Supabase 프로덕션 키, 환자 데이터가 든 테이블에 대한 쓰기 권한은
> Claude 세션에 절대 노출하지 않는다. 스테이징/더미 데이터로 작업한다.
