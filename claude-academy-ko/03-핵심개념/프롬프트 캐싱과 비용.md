# 프롬프트 캐싱과 비용
> [!tip] 한 문장
> 매번 똑같이 들어가는 앞부분(시스템 프롬프트, 문서)은 **캐시해서 값싸게** 재사용한다.

---

## 비용 구조
- 요금은 **입력 토큰 + 출력 토큰**으로 계산된다
- 대화가 길어질수록 매 턴 **전체 히스토리**가 다시 입력된다 → 비용이 누적 증가

## 캐싱이 먹히는 조건
- 프롬프트의 **앞부분이 바이트 단위로 동일**해야 한다
- 그래서 **변하지 않는 것을 앞에, 변하는 것을 뒤에** 배치한다

```
[시스템 프롬프트][긴 참조 문서][도구 정의]  ← 캐시 대상 (고정)
[대화 히스토리][이번 질문]                  ← 매번 변함
```

---

## 비용 줄이는 실전 순서
1. 불필요한 자료를 안 넣는다 (가장 효과 큼) → [[컨텍스트 관리]]
2. 고정 접두부를 캐싱한다
3. 작업 난이도에 맞는 모델을 고른다 (전부 최상위 모델일 필요 없음)
4. 출력 길이를 제한한다
